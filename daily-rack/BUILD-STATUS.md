# Build status

Status date: October 28, 2026. Feature IDs follow [`docs/handoff/04-delivery/BUILD-BACKLOG.csv`](docs/handoff/04-delivery/BUILD-BACKLOG.csv).

**Summary:** Daily Rack is now one Expo app (iOS, Android and web) with two halves. The daily rack loop works end to end: open the rack, pass three tiles, compare with one strong pass and the community split, and export a real 1080×1920 MP4. On top of that, players can sit down to full games of American mahjong against computer players or with friends, live or turn-based, add friends by code, chat, and plan in-person Game Nights with an online table as the fallback. Everything below marked *verified* was exercised in headless Chromium against the Expo web build; the iOS and Android bundles compile, but **no native build has been run on a device yet**. There is deliberately no sign-in: every player is a guest identified by their device. Chat has the safety tools App Store review asks for: community rules, a word filter, reporting, blocking and moderator tools. Newer additions: push notifications and on-phone reminders, Pip the sparrow and a Learn tab for new players, iPad layouts, drag-to-arrange tiles, dead-hand calls and "why can't I call this?" explanations. What remains before launch: device testing, teacher-reviewed content, the lawyer's card review, checking ten lines of the 2026 card against an official card (the printed tracker it came from has errors there; see `content/cards/README.md`), the Expo push setup, and store builds.

## Decisions that differ from the handoff

| Handoff proposal | What was built | Why |
| --- | --- | --- |
| Expo / React Native app plus a small web route | One Expo Router app for iOS, Android and the web; the server hosts the web export, so shared links still play with no install | Matches the handoff. The clip renderer is canvas and WebCodecs code, so native builds run it in a WebView of the web build and receive the MP4 over the bridge for the share sheet or Photos. |
| Encoder chosen in F00 | WebCodecs H.264 via Mediabunny, VP9/AV1 fallback | Hardware or software H.264 exists in current Safari and Chrome; verified here in Chromium |
| Audio codec chosen in F00 | AAC when the browser has it, otherwise Opus | Linux Chromium has no AAC encoder, so the verified voiceover export used Opus. iPhones support AAC. Check that Instagram accepts Opus-in-MP4 if Android exports need it. |
| Provider choices open | Node + Hono + SQLite (built into Node 22) | Small, no paid services; swap to Postgres when hosting is chosen |
| No multiplayer in the P0 scope | Full four-seat games, friends, chat and Game Night (added at the owner's request) | The owner asked for real games with friends, live or turn-based, plus in-person game planning |
| Card to be decided after legal review | Games use an original house card (33 hands, eight sections) | Real play needs a card; the League card can't be copied without a licence |

## Before launch

1. Run F00 on real devices: a baseline iPhone (Safari) and a mid-range Android phone (Chrome). Measure export time, memory and file size, and check playback after upload to Instagram and TikTok.
2. Get a teacher to review the first 14 racks, then set `teacherReviewed`.
3. Get a lawyer to review how racks refer to the card, and decide between an original practice card, a League licence, or both.
4. Pick the app name and run a trademark check.
5. Add privacy, support and terms pages. (Hosting is done: the server runs on Railway at https://daily-rack-production.up.railway.app with a persistent volume; turn on volume backups in the dashboard.)
6. Try the app on an iPhone in Expo Go from a Codespace (`API_URL=https://daily-rack-production.up.railway.app npm run phone`, see the README), then set up EAS builds for TestFlight and Play internal testing with `EXPO_PUBLIC_API_URL` set to the Railway address.
7. `ADMIN_TOKEN` is set on Railway. Contact us messages from the app are stored and listed with `npm run reports feedback`, and problem reports with `npm run reports -- bugs`; add `SUPPORT_EMAIL` (shown next to the form) and ideally `REPORT_WEBHOOK_URL` (pings for reports and messages), decide who reviews reports every day, and paste the App Review note from `docs/MODERATION.md` into the submission.
8. Set up Plus for sale (see the README): App Store Connect and Play Console products, RevenueCat store credentials, `REVENUECAT_SECRET_KEY`, and `PRIVACY_URL`/`TERMS_URL`. Then make a sandbox purchase on a device and check the server sees it.
9. Finish the push setup: `npx eas-cli@latest init` in `apps/mobile`, then APNs and FCM V1 keys with `eas credentials`. Update the App Store privacy label and Play data safety form for push tokens and problem reports.
10. Have a teacher review the house card and its point values.
11. Store rules found on October 28, 2026 (re-check before submitting):
    - Apple: uploads must be built with Xcode 26 / iOS 26 SDK now, and with Xcode 27 / iOS 27 SDK from April 2027.
    - Apple: answer the age-rating questionnaire. It now has 4+, 9+, 13+, 16+ and 18+ tiers. Declare user chat. The "social media" question is mandatory: clips shared out through the share sheet shouldn't count, but an in-app feed would.
    - Apple: Guideline 1.2 covers random and anonymous chat. Never switch a feature on after review (new guideline 2.5.19).
    - Google Play: target API 36. Expo SDK 58 already does.
    - Age laws: Texas (since June 2026), California and Alabama (January 2027), Utah (May 2027) and Louisiana (July 2027). Adopt Apple's Declared Age Range API and the related StoreKit and PermissionKit pieces, and Google Play's Age Signals API.
    - Accessibility Nutrition Labels: optional for now. Fill them in early.
12. Every leading American mahjong app ships the current NMJL card or another publisher's card (Marvelous, Mah Jongg Press, Big Card, AMS). Our house card is the biggest gap against them. Take the card question (item 3) to the lawyer early.
